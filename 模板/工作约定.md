# 求职工作约定

## 资料

- 每次操作读取最新 `00_基础资料/个人资料.md`，它是个人事实的唯一来源。
- 聊天中新增的事实先确认，再写回个人资料；翻译、精简和改写保持原有事实。
- 空白表示未知；必填缺失时指出字段并暂停提交，选填无依据时留空。
- 附件只读取文件名、扩展名和大小；内容与原始简历不参与事实填写。
- 附件路径统一登记在个人资料末尾，经历使用唯一附件编号关联。

## 浏览器

- 页面操作统一使用 `edge-control` MCP 与 `edge-browser-ops` Skill。
- 从 `edge_list_tabs` 获取真实标签页 ID；导航和抓取默认使用后台标签。
- 读取使用 DOM；填写使用页面元素事件；长文本填写后失焦回读。
- 文件上传使用 `edge_send_cdp` 注入文件输入，并回读文件状态。
- bridge 不可用时运行环境配置 Skill 的修复步骤。

## 申请

- 公司官网或官方招聘页用于确认岗位、资格和投递规则；学校就业网、公众号、BOSS直聘和公开 ATS 用于发现岗位与补充信息。
- 官网支持解析时，先上传简历、等待解析结束，再按个人资料逐字段清洗。
- 技能选项按页面全部选项与已确认技能进行匹配。
- 只上传页面要求的附件；英文要求上传英文版，未指定时默认中文版。
- 登录、验证码和人机验证由用户处理；正式测评不代做。
- 全表回读后进入待提交，用户授权本次提交后执行。
- 只有页面成功回执记录申请编号与提交时间。

## 记录

- 用户入口为 `90_投递总览.md`、`公司总览.md` 与 `APP-*.md`。
- 招聘链接、投递限制、人数和薪资记录官方来源与查询日期。
- 同表多个志愿只建一个 APP。
- 填写映射与页面快照放入 `_AI内部/`，阶段结束后把结论合并进 APP 并清理。
- 申请状态区分待填写、填写中、待提交、已提交、测评中与已结束。
- 测评完成记录为“已完成”，结果以官网或用户确认的记录为准。
