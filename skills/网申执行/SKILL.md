# 网申执行

读取工作区约定、当前个人资料、目标公司总览和 APP；新工作区约定模板见 [工作约定](../../模板/工作约定.md)。浏览器操作前必读 [Edge配置](../环境配置/references/Edge配置.md) 和已安装 `edge-browser-ops` Skill。只通过 Edge Control 的实际 MCP 工具操作用户现有 Edge；缺失或断线暂停，不调用 Codex 内置浏览器、Computer Use、`cua_repl` 或其他浏览器工具。先 `edge_bridge_status` 再 `edge_list_tabs`，不依赖历史句柄或页面状态。

## 执行

1. 核验账号当前申请记录；已有申请时避免重复提交，优先查看进度。用户明确更新状态也应记录来源，不强迫重新申请或用旧记录覆盖。
2. 确认岗位和志愿已由用户选择，检查真实页面条件、必填字段、字符限制、附件语言格式大小。将每个拟填字段映射到源章节/记录编号及必要摘录；不存完整页面转储。
3. 从附件登记按编号解析路径，先上传简历并等待解析结束，再逐字段回读清洗；没有自动解析才直接手填。源文本不足则请用户编辑准确字段。隐藏的条件字段不主动填，无依据的解析字段必须清除。
4. 通过 DOM 定位操作，一次修改一个长文本并失焦回读；技能完整匹配全部选项，翻译和截短不改变事实。不直接改 React/框架内部状态、不绕过网站校验或调用未授权提交接口。
5. 对应字段上传附件后记录实际文件名和成功/错误结果。附件候选不能改写为“已上传”。版本或路径不明时停在该项，不读文件正文消除疑问。
6. 全表回读实际值，按 APP 的字段来源核对，处理必填错误。将申请置为待提交；列出岗位志愿、重要声明、未解决项及准确提交动作，取得本次授权。登录、验证码、人机验证、隐私协议确认和正式测评交用户。
7. 提交发生错误或超时先检查申请记录及成功回执，不能盲目重复点击。以用户明确确认或官网回执记录结果来源，只有回执才称“官网确认”；不知道编号或提交时间就留空，不杜撰。

## 收尾和跟进

同步 APP、公司总览和投递总览；测评独立记录未通知/已邀请/已完成/结果，不将完成写成通过。用户确认日期与实际事件日期分开。

提交后将同一 APP 收敛为结果记录：入口、志愿、已知实际附件、关键确认与确有记录的答复、状态和来源。不能把拟稿冒充已提交答案；删除自己产生的临时映射和快照前保留必要结论，不删用户资料。待面试或通知，不再要求重填已完成申请。
