# 环境配置

1. 确认用户指定的工作区与插件目录；插件目录用于分发，个人资料存用户工作区。先读工作区现有约定；新工作区复制 [工作约定](../../模板/工作约定.md) 为 `AGENTS.md`，不覆盖已有文件。后续操作遵守该约定。
2. 检查当前可调用浏览器工具并读取其文档。用无个人数据的空白页或本地测试表单验证页面读取、元素定位、填写、选项设置、回读、文件上传能力。未经实测的项写“未验证”，不能因文件存在就宣布环境可用。上传测试只用虚构附件。
3. 优先现成 DOM/浏览器协议工具；查清工具来源和官方安装说明，再针对缺项逐步指导安装、启用浏览器扩展、连接及必要重启。不得虚构 MCP 工具名、下载地址或写死当前机器路径。安装与配置变更先说明具体作用，遵守所在环境授权规则。
   当前工具若报告上传需要扩展的“允许访问文件 URL”权限，指出对应扩展详情页及官方说明，由用户决定并处理；未启用时上传写“受阻”，不能声称上传成功。其他浏览器或工具以自身文档为准。
4. 只在脚本执行需要时检查 Node.js（18+）；没有 Node 仍可人工维护资料，不默认安装 Python。浏览器无法连接时保留已完成的初始化工作，说明准确阻塞点和用户操作，不切换截图鼠标模式。
5. 报告 DOM 读取、填写回读、上传各自结果；不承诺所有操作不抢焦点，文件选择和认证需单独验证。环境已通过则交接资料管理，不重复安装。

用户只需知道：哪些可用、缺什么、下一步。不生成独立环境报告；必要阻塞写投递总览。
